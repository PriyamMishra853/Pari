          A second pair of eyes for experiments in orbit
          
      
          An astronaut runs a science procedure on the space station. PARIKSHAK watches through a camera,
        checks every step against the procedure file, and speaks up only when it is sure something went wrong — always
        saying which step and why. When it cannot see, it says so instead of guessing.
          
    
          

    
          From camera to spoken alert
          
    
          
      
          
        
          Camera
          
        
          Watches the experiment rack. Video never has to leave the station.
          
      
          
      
          
        
          Perception
          
        
          Finds the rack from its corner markers, then each object, its state and where hands are.
          positions in rack metres
      
          
      
          
        
          Belief frame
          
        
          What is seen, with confidence. Hidden stays "unknown" — never "absent".
          BeliefFrame
          v1.1, 5–10 per second
      
          
      
          
        
          Procedure engine
          
        
          Checks each step's conditions, accumulates evidence over time, and watches safety rules.
          14-step CSP-1, 8-step CRX-2
      
          
      
          
        
          Crew & ground
          
        
          Voice prompt and alert, checklist on screen, and a tamper-evident log sent down first.
          ~8 KB per run vs ~70 MB of video
      
          
    
          

    
          The ideas that make it trustworthy
          
    
          
      
          
        
          The procedure is a file
          
        
          Steps, objects, zones and safety rules are written in a procedure file. A new experiment is a new file — the
          second experiment here needed no retraining and no code change.
          
      
          
      
          
        
          Unknown is not wrong
          
        
          If the crew's body blocks the camera, the step reads "cannot verify", never "skipped". An alarm needs
          evidence against the step, not missing evidence.
          
      
          
      
          
        
          Every alert has a reason
          
        
          "Step eight, close the glovebox latch, was not completed" comes with the condition that failed and when. A
          reviewer can check every decision.
          
      
          
      
          
        
          Up is the rack, not gravity
          
        
          Positions are measured against markers on the rack, so rotating the rack or floating upside down changes
          nothing the engine reasons with.
          
      
          
      
          
        
          Offline and auditable
          
        
          No network code in the on-board software. Each run writes a hash-chained log: change one byte and
          verification names the record that was altered.
          
      
          
      
          
        
          Beyond sequence: safety
          
        
          Opening the latch while the unit runs skips no step, so a checklist cannot see it. A safety rule that must
          hold throughout the step catches it.
          
      
          
    
          

    
          What is real in this demo
          
    
          
      
          
        
          Real
          
        
            
          
          • The procedure engine: every prompt, tick, alert and reason here is its output — in guided runs it is
            deciding live, frame by frame, as you act.
            • 
          
          • Both procedure files and the hash-chained log with its verification.
            • 
          
          • A live mode on a laptop webcam with printed markers (parikshak run), and a
            desktop operator window.
            • 
        
          
      
          
      
          
        
          Simulated or not yet built
          
        
            
          
          • The camera. Guided runs drive the world model that generated the test corpus; recorded runs are synthetic,
            with noise, drops and occlusion.
            • 
          
          • Objects are recognised through printed markers; no trained object or hand-tracking model exists yet.
            • 
          
          • Not yet run on the Jetson edge computer, so no power measurement.

          Honest limits
          
    
          
      
          Synthetic data
        
          The evaluation runs are generated and degraded, not recorded on orbit or in a lab. Real footage will be
          harder.
          
      
          
      
          No trained models yet
        
          Objects are seen through printed markers. Without hand tracking, a live webcam run cannot verify steps that
          need hands and waits at the first one — without raising a false alarm.
          
      
          
      
          Edge hardware
        
          Speed is measured on a laptop CPU only. The target of at least 10 frames per second within 25 W needs a
          Jetson and a power meter.
          
      
          
      
          Rushed steps behind a blind spot
        
          If the camera was blocked just before a rushed step, the engine gives the crew the benefit of the doubt, and
          can miss it.
